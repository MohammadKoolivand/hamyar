# جریان‌های واقعی هدهده — تمرکز آموزش فردی

این سند با پیاده‌سازی فعلی هدهده هماهنگ است. سناریوی دوازده‌مرحله‌ای با پایگاه داده واقعی و داده‌های **کاملاً مصنوعی** در `tests/integration/full-individual-journey.test.ts` اجرا می‌شود. هر بخشِ محدودشده در ادامه صریح ذکر شده است.

## فلو ۱۲مرحله‌ای معلم خصوصی → دانش‌آموز → والد

| مرحله | بازیگر | مسیر صفحه | اقدام و نتیجه قابل سنجش |
|---|---|---|---|
| ۱ | معلم | `/` | ثبت‌نام مستقل معلم؛ ورود و ایجاد نشست امن |
| ۲ | معلم | `/courses` | ایجاد درس فعال «ریاضی دهم» |
| ۳ | معلم | `/content` | ایجاد «مبحث» و «مهارت» با parentId معتبر متعلق به همان معلم |
| ۴ | معلم | `/content` | ذخیره پنج نسخه سؤال با پاسخ مرجع خصوصی، مهارت و راهنما؛ بانک خصوصی قابل مشاهده توسط دانش‌آموز/والد نیست |
| ۵ | دانش‌آموز و معلم | `/`، `/students`، `/courses` | ثبت‌نام مستقل دانش‌آموز؛ صدور دعوت موبایل‌محور (ایمیل قدیمی سازگار است) از طرف معلم؛ پذیرش در حساب موجود؛ عضویت فعال در همان درس |

| ۸ | موتور ارزیابی | API محافظت‌شده | نتیجهٔ عددی بر اساس پاسخ مرجع؛ ردیابی تلاش و کمک؛ پشتیبانی از پاسخ نیازمند بررسی معلم برای انواع غیرقطعی؛ بدون نشت کلید پاسخ |
| ۹ | معلم | `/report?assignment=<uuid>` و `/learning` | مشاهده گزارش: ۵ پاسخ، ۳ صحیح مستقل، ۱ صحیح با کمک، ۱ غلط؛ دفترچه اشتباهات و شواهد مهارت قابل بازیابی |
| ۱۰ | معلم | `/homeworks` | انتخاب دانش‌آموز → درس فعال به‌صورت پیش‌فرض → پیشنهاد فقط آخرین خطاهای معتبر و فاقد **تمرین تقویتی باز** → انتشار مأموریت فردی |
| ۱۱ | دانش‌آموز | `/practice?assignment=<uuid>` | حل مستقل سؤال تقویتی بدون راهنما؛ پایان مأموریت، گزارش مستقل و به‌روزرسانی شواهد. اگر نتیجهٔ تازه صحیح باشد، سؤال از پیشنهاد خطای جاری حذف می‌شود |
| ۱۲ | والد | پذیرش دعوت، پنل والد | صدور دعوت سرپرست توسط معلم؛ پذیرش؛ مشاهده فقط گزارش مربوط به رابطهٔ مجاز؛ عدم اجازه ثبت پاسخ، مصرف راهنما یا دسترسی به داده خصوصی معلم/دیگر دانش‌آموزان |

### مسیرهای جایگزین معتبر
- درخواست عضویت درس با کد ۷۲ساعته و تأیید معلم، جایگزین دعوت مستقیم است؛ داشتن کد به‌تنهایی عضویت ایجاد نمی‌کند.
- دانش‌آموز می‌تواند با همان حساب، به چند معلم و درس متصل شود؛ هر گزارش به معلم/دانش‌آموز/عضویت خودش محدود است.
- سؤال تشریحی یا ارزیابی نامطمئن به `pending_review` می‌رود؛ نتیجه را فقط معلم مجاز تعیین می‌کند. این وضعیت به‌عنوان «درست» یا «اشتباه قطعی» برای تمرین تقویتی استفاده نمی‌شود.
- مأموریت تقویتی در حالت `published`، `in_progress` یا `submitted` یک پیشنهاد باز محسوب می‌شود. صدور دستی نسخهٔ دیگر از **همان پیشنهاد باز** در مسیر remediation رد می‌شود. پس از تکمیل/لغو، فقط در صورت وجود خطای معتبرِ تازه امکان پیشنهاد مجدد وجود دارد.
- نتیجهٔ «correct after hints» از «independent correct» جداست؛ عدد نهایی به معنی اثبات تسلط علمی نیست.
- والد از طریق دعوت معلم متصل می‌شود؛ **احراز حقوقی سرپرستی، رضایت کودک و سیاست نگهداری/حذف داده برای پایلوت عمومی هنوز تکمیل نشده است**.

## دستور بررسی

`npm run typecheck && npm run lint && npm run build && npm test`

تست‌های مرورگر با `npm run test:e2e` پس از آماده‌شدن Replica Set. آزمون سرتاسری ۱۲مرحله‌ای نیازمند همان MongoDB آزمایشی است و هیچ‌وقت روی دیتابیس دارای داده واقعی کودک اجرا نشود.

## معماری و نمایش
- هر تب مسیر مستقل دارد: `/dashboard`، `/courses`، `/students`، `/content`، `/homeworks` و `/learning`.
- تصحیح/تلاش/راهنمایی/تخصیص تکلیف دادهٔ واقعی هستند؛ آمار ساختگی در داشبورد تولید نمی‌شود.
- تمرکز MVP، تمرین فردیِ دانش‌آموز با هدایت معلم است. کلاس‌های گروهی قابلیت جداگانه‌اند و پیش‌نیاز این فلو نیستند.
