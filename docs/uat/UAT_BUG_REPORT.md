# UAT — گزارش نقص‌ها و بازآزمایی

## UAT-OCR-001 — P1 — اصلاح‌شده و تأییدشده

- Test Case: OCR-009 / OCR-011 / EDGE-009.
- Expected: شش سؤال شماره‌دار صفحه دوم PDF واقعی کنکور ریاضی ۱۴۰۵ جدا باشند؛ خروجی نامطمئن همچنان بازبینی شود.
- Reproduce: `pdfseparate -f 2 -l 2 .private/imports/konkur1405/source.pdf /private/tmp/hodhodeh-uat-real-exam/source-%d.pdf` سپس `docs/uat/real-exam-probe.ts`. این کپی فقط‌خواندنی فایل عمومی معرفی‌شده مالک است؛ بانک اصلی تغییر نمی‌کند.
- Actual before: `[1,2,5,6]`؛ ۳ و ۴ در سؤال دوم ادغام می‌شدند. تصاویر و هشدار بازبینی باقی بودند و سؤال خودکار منتشر نشد.
- Root cause: محافظ قبلیِ جلوگیری از anchor کاذب گزینه ۴، تمام anchorهای بدون برچسب ۱–۴ را پس از گزینه ناقص مبهم می‌دانست؛ حتی شماره سؤال واقعی با dash در text layer و راست‌چین هم‌تراز.
- Changed file: `src/server/imports/layout.ts`.
- Fix: استثنای محدود و عمومی برای heading مستقیم text، شماره بعدی متوالی، جداکننده dash، عرض قابل‌مقایسه و هم‌ترازی راست با heading پیشین. خط OCR و گزینه کوتاه/تورفته از این قاعده استفاده نمی‌کنند. هیچ شماره یا نام فایل fixture در منطق محصول hardcode نشد. هشدار بازبینی/کلید و الزام تأیید انسانی حفظ شد.
- Regression: `tests/unit/document-layout.test.ts`، تست «aligned sequential text headings…». قبل: ۵ pass / ۱ fail؛ بعد: ۶ pass / صفر fail؛ حالت گزینه مبهم و تست anchor قدیمی حفظ شدند.
- Real sample after: `[1,2,3,4,5,6]`. این فقط تشخیص مرز روی همان صفحه است؛ صحت علمی متن، فرمول و گزینه‌ها و کلید خودکار هنوز تأیید کامل ندارند.
- Data impact: هیچ داده واقعی/بانک موجود اصلاح یا بازنویسی نشد. اصلاح باید با build/release بعدی اعمال شود؛ نسخه UAT بازسازی شد.
- Final gate: backend ۱۳۲/۱۳۲؛ browser ۳۷ pass/صفر fail/یک skip مستقل مدل واقعی. مدرک: evidence/backend.log و e2e-final.log.
- Regression risk: متن کوتاه یا layout متفاوت ممکن است همچنان نیاز به تقسیم دستی داشته باشد. این parser جایگزین review معلم نیست.

## UAT-AI-001 — P2 — باز: کیفیت راهنمای پیش‌نویس محلی

- Case: AI-008 برابر FAIL. مدل واقعی محلی qwen2.5:3b در سه تولید متوالی برای جمع ۳+۴، پاسخ نهایی ۷ را داخل راهنمای پیش‌نویس آورد؛ نمونه صریح «پاسخ مرجع فقط عدد 7 است.» در `evidence/authoring.json` ثبت است.
- Root cause: پیروی معنایی مدل کوچک از دستور «without final answer» قابل تضمین نیست؛ schema فقط قرارداد داده را بررسی می‌کند. parse موفق به معنی کیفیت آموزشی موفق نیست.
- Scope: این خروجی‌ها فقط پیش‌نویس آزمایشی بودند؛ published=0. تأیید/اصلاح انسانی قبل از بانک و انتخاب راهنمای تأییدشده برای tutor برقرار است. افشای خودکار پاسخ به دانش‌آموز در این probe رخ نداد.
- Decision: باز نگه داشته شد. جایگزینی مدل، تغییر گسترده generation یا ادعای حل نشت معنایی با regex در Feature Freeze انجام نشد. معلم باید این راهنماها را رد/بازنویسی کند. قبل از فعال‌سازی تولید خودکار با این مدل، benchmark آموزشی داوری‌شده لازم است. این نتیجه به مدل پولی AvvalAI تعمیم ندارد.
- Priority P2 است چون خروجی غیرمنتشرشده و gate انسانی موجود است؛ اگر بررسی انسانی برداشته شود، مانع انتشار خواهد بود.

## محدودیت‌ها — بدون افزودن فیچر خارج از MVP

- کلید PDF واقعی دارای متن با encoding نامطمئن است؛ پیش‌پرکردن خودکار معتبر برای نمونه شش‌سؤالی تأیید نشد و تمام موارد `needs_review` ماندند. OMR یا بازسازی حدسی کلید اضافه نشد.
- نسخه فعلی، نمایش اختصاصی ID نسخه سؤال و فیلتر مستقل skill در بانک ندارد؛ deadline مأموریت هم پیاده نیست. این موارد NOT_IMPLEMENTED هستند، نه PASS یا باگ رفع‌شده.
- UI و metadata برند هدهده دارند؛ عنوان هدهد در این مأموریت با نام قبلاً تأییدشده تعارض دارد. OWNER DECISION؛ بازنام‌گذاری خودسرانه انجام نشد.
- محدودکننده ۱۲۰ درخواست/دقیقه در اجرای سریع UI قابل برخورد است. سقف امنیتی افزایش نیافت؛ آزمون به سرعت کنترل‌شده و retry محدود GET مطابق Retry-After مجهز شد. این اجرای پذیرش، benchmark ظرفیت کلاس نیست.
- پیش‌نیازهای عملیاتی و سرویس‌های خارجی در UAT_RELEASE_READINESS ثبت می‌شوند؛ نبود HTTPS یا credential به‌عنوان نقص حل‌شده معرفی نمی‌شود.

## خطاهای harness و محیط، جدا از نقص محصول

اجرای اولیه واحد در sandbox دو خطای EPERM برای bind پورت داشت؛ اجرای مجاز ۴۶/۴۶ موفق شد. در توسعه تست Golden، locator بخش جمع‌شده/متن راهنما، انتظار ناکافی ذخیره/انتشار/تغییر URL و مقایسه نادرست projection معلم/دانش‌آموز اصلاح شد. داده‌های خروجی برای نقش‌ها یکسان نیستند؛ مقایسه دقیق همه شمارنده‌های عمومی و حفظ projection خصوصی انجام می‌شود. یک اجرای هم‌زمان نیز artifactهای Playwright را پاک کرد؛ output مستقل تعیین شد. این اجراها PASS محسوب نشدند و لاگ‌های اولیه حفظ شده‌اند. هیچ assertion مربوط به شمارنده، جداسازی دسترسی، نتیجه تصحیح یا مرجع پاسخ ضعیف نشد.

به‌دلیل فاصله عمدی ۶۵۰ms برای هر درخواست و burst حدود ۱۵ درخواست در refresh، انتظارهای تست جدید تا ۲۰s و کل سناریوی چندکاربره تا ۳۰۰s مستند شده‌اند؛ timeout سرویس/برنامه و محدودکننده تولیدی تغییر نکردند. GET تشخیصی فقط یک بار پس از Retry-After تکرار می‌شود؛ پاسخ مصنوعی یا mock برای پوشاندن خطا تولید نمی‌شود.
