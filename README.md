# HamYar — همیار

Next.js تمام‌استک، TypeScript، Tailwind CSS و MongoDB. رابط فارسی RTL؛ Poppins محلی و IRANSans دارای لایسنس دستگاه با next/font/local و fallback فارسی. یک برنامه Node.js، یک پایگاه داده، بدون monorepo یا سرور API جدا.

## ساختار

```text
src/
  app/             صفحات، layout و Route Handlerهای Next.js
  features/        صفحه‌ها و جریان‌های auth/content/missions/practice/analytics/parents
  components/      orchestration و مؤلفه‌های ui
  server/          اتصال MongoDB، نشست، ارزیابی و ماژول‌های آموزشی
  lib/             نوع‌های مشترک
  assets/fonts/    فونت‌های محلی
public/            آیکن و manifest
scripts/           تولید service worker از build
tests/            unit، integration و e2e
docs/             PRD، معماری، قرارداد API و وضعیت اجرا
```

## اجرا

Node.js 22+ و MongoDB replica set لازم است؛ برنامه روی MongoDB standalone به‌صورت ناامن اجرا نمی‌شود.

```sh
npm ci
cp .env.example .env
docker compose up -d mongo
# After 'docker compose ps' shows mongo healthy:
npm run dev
```

آدرس: http://127.0.0.1:5174. اسکریپت‌های dev/start از CLI رسمی Next.js استفاده می‌کنند؛ بارگذاری `.env` توسط خود Next.js انجام می‌شود و نباید گزینه `--env-file-if-exists` داخل NODE_OPTIONS قرار گیرد. MongoDB پیش‌فرض روی 27017؛ برای MongoDB دیگر MONGO_URL را در .env تنظیم کنید. برای نمونه مجزا:

```sh
mkdir -p .data/mongo
mongod --dbpath .data/mongo --replSet hamyar-rs --bind_ip 127.0.0.1 --port 27019 --logpath .data/mongo.log
```

در این حالت MONGO_URL=mongodb://127.0.0.1:27019/?replicaSet=hamyar-rs باشد. برای MongoDB محلی تازه، پس از شروع mongod یک بار `npm run mongo:init` را با MONGO_URL درست اجرا کنید و تا primary شدن صبر کنید.

Docker اختیاری: `docker compose up -d mongo`.

تولید: `npm run build` سپس `npm start`. در استقرار عمومی HTTPS و COOKIE_SECURE=true لازم است؛ APP_ORIGIN باید origin برنامه باشد.

## عیب‌یابی اجرا روی مک

- `npm run dev` اکنون قبل از اجرا آزادبودن پورت 5174 روی `127.0.0.1` را بررسی می‌کند و پیام راهنما می‌دهد. هیچ فرایندی را خودکار متوقف نمی‌کند.
- اگر پورت اشغال است، ابتدا `lsof -nP -iTCP:5174 -sTCP:LISTEN` را اجرا کنید. اگر همان همیار از قبل اجراست، مرورگر را در `http://127.0.0.1:5174` باز کنید؛ وگرنه تنها پردازشی را که متعلق به شما و قابل‌توقف است با `kill <PID>` متوقف کنید.
- اگر پس از اجرای مستقیم Next.js هنوز `NODE_OPTIONS` خطا می‌دهد، مقدار متغیر محیطی را در shell و فایل‌های پیکربندی بررسی کنید. به‌طور معمول `unset NODE_OPTIONS` و بازکردن یک ترمینال جدید کافی است؛ فلگ `--env-file-if-exists` را در `NODE_OPTIONS` قرار ندهید.
- برای خطای اتصال MongoDB، `docker compose ps` باید وضعیت `healthy` را نشان دهد. MongoDB حتماً باید replica set باشد.
- برای مرورگر تست Playwright روی دستگاهی که Chrome ندارد: `npx playwright install chromium`؛ در صورت تمایل `CHROME_PATH` را به باینری محلی تنظیم کنید.

## استفاده

ثبت‌نام مستقل معلم یا دانش‌آموز ← ورود به پنل. معلم درس/مبحث و سؤال مرجع‌دار ایجاد می‌کند و دعوت را به ایمیل دانش‌آموز می‌سازد. دانش‌آموز عضو شده از بخش «اتصال به معلم» کد را وارد می‌کند؛ دانش‌آموز فاقد حساب می‌تواند با لینک دعوت حساب بسازد. بعد از اتصال، معلم مأموریت منتشر می‌کند و دانش‌آموز تمرین و گزارش را می‌بیند.

ایمیل دعوت ارسال نمی‌شود؛ لینک را معلم منتقل می‌کند. Mock Provider فقط راهنمایی‌های تأییدشده معلم را ارائه می‌دهد. با AI_PROVIDER=ollama مدل محلی از گزینه‌های مجاز معلم انتخاب می‌کند؛ متن آزاد تولیدشده نمایش داده نمی‌شود. تشریحی به بررسی انسانی می‌رود. داده و آمار نمایشی وجود ندارد.

استایل رابط فقط کلاس‌های Tailwind در JSX است. `src/app/globals.css` تنها شامل import ضروری Tailwind است؛ فونت‌ها با next/font/local ثبت می‌شوند. مؤلفه Button از الگوی shadcn/Radix استفاده می‌کند.

## مهاجرت و یکپارچگی P0

قبل از تغییر MongoDB قدیمی، نوشتن برنامه را متوقف و نسخه پشتیبان نگه دارید. `MIGRATION_SOURCE_URL=<old> MONGO_URL=<new replica> MONGO_DB=<name> npm run migrate:replica` فقط به مقصد کاملاً خالی کپی می‌کند و مبدأ را تغییر نمی‌دهد. کپی غیرتراکنشی است؛ در صورت قطع، مقصد ناقص را به‌عنوان معتبر استفاده نکنید. سپس `npm run audit:integrity` را اجرا کنید؛ مغایرت قدیمی برای بازبینی گزارش می‌شود و شواهد ساختگی/شماره‌گذاری مجدد تولید نمی‌شود.

درخواست‌های حساس `Idempotency-Key` می‌پذیرند؛ رابط برای تلاش/کمک کلید را به intent و شمارنده تأییدشده متصل می‌کند. استفاده مجدد کلید با body متفاوت 409 می‌دهد. بدون کلید، هر درخواست برای سازگاری یک intent جدید است.

مالک داشتن لایسنس IRANSans برای نسخه توسعه آزمایشی را اعلام کرد. فایل دستگاه در `.private/fonts/IRANSansXFaNum-Regular.ttf` (ignored) حفظ شده؛ predev/prebuild آن را به فایل تولیدی ignored کپی و با next/font/local در build همین دستگاه بارگذاری می‌کند. در checkout فاقد فایل مجاز، Poppins و fallback سیستمی استفاده می‌شوند. فایل IRANSans وارد Git نمی‌شود؛ حق بازتوزیع عمومی و تاریخچه قبلی مخزن جداگانه باید بررسی شوند. حذف تاریخچه یا push انجام نشده است.

## همیار محلی

برای مدل موجود روی Ollama، AI_PROVIDER=ollama و OLLAMA_MODEL=qwen2.5:3b را در .env تنظیم و برنامه را restart کنید. OLLAMA_BASE_URL پیش‌فرض http://127.0.0.1:11434 و AI_TIMEOUT_MS پیش‌فرض 30000 است. AI_FALLBACK=mock فقط در صورت انتخاب صریح شما در قطعی به راهنمای آزمایشی بازمی‌گردد؛ نوع واقعی هر رویداد در UI/metadata مشخص است. مدل باید از قبل نصب/سرویس در دسترس باشد؛ برنامه مدل یا اشتراک خریداری نمی‌کند. `node --import tsx scripts/smoke-ollama.ts` دو درخواست مصنوعی واقعی اجرا می‌کند؛ به داده دانش‌آموز دسترسی ندارد.

## تولید سؤال و پنل اولیا

معلم علاوه بر ورود دستی سؤال می‌تواند در بانک محتوا، مبحث و پایه/هدف را مشخص و یک پیش‌نویس با Ollama واقعی تولید کند. پیش‌نویس از بانک جداست؛ معلم متن، پاسخ و راهنماها را اصلاح و تأیید یا با دلیل رد می‌کند. فقط تأیید، نسخه سؤال قابل تخصیص می‌سازد. در حالت Mock تولید سؤال غیرفعال و صریح است؛ پاسخ ساختگی به‌عنوان AI نمایش داده نمی‌شود. AI_AUTHOR_TIMEOUT_MS و OLLAMA_AUTHOR_MODEL قابل تنظیم‌اند.

در دانش‌آموزان ← دسترسی اولیا، معلم برای ولی همان دانش‌آموز دعوت جداگانه می‌سازد. ولی پس از پذیرش و ورود، گزارش خواندنی و شواهد یادگیری همان ارتباط را می‌بیند؛ امکان پاسخ، راهنمایی، تغییر نمره یا دیدن یادداشت خصوصی معلم ندارد. معلم می‌تواند این دسترسی را لغو کند. این اتصال فنی جایگزین احراز سرپرستی یا رضایت لازم برای پایلوت نیست.

بازسازی افزایشی شواهد قبلی: `npm run rebuild:learning` فقط پس از توقف نوشتن؛ سپس `npm run audit:integrity`. ابزارهای عملیاتی: `npm run ops:status`، `npm run smoke:load` و `WRITES_PAUSED=true npm run verify:backup`؛ شرایط و محدودیت‌ها در [آمادگی پایلوت](docs/PILOT_READINESS.md) ثبت شده‌اند. محصول هنوز برای پایلوت با داده واقعی کودک آماده اعلام نشده است.

## نسخه ثبت‌نام مستقل دانش‌آموز

در صفحه ورود گزینه‌های جداگانه «ثبت‌نام معلم» و «ثبت‌نام دانش‌آموز» وجود دارند. ثبت‌نام دانش‌آموز **کد دعوت نمی‌خواهد** و در پنل او وضعیت بدون مأموریت و فرم اتصال به معلم نمایش داده می‌شود. کد دعوت فقط به ایمیلی که معلم دعوت کرده محدود است؛ دانش‌آموز می‌تواند از همان حساب به چند معلم متصل شود. تمرین مستقل از بانک عمومی در این نسخه **هنوز پیاده‌سازی نشده است**. برای بررسی خودکار تغییرات: `npm run check` و `npm run test:e2e` با Replica Set فعال و مرورگر Playwright.

## چند درس و چند معلم (Course / Enrollment)

در پنل معلم «درس‌های من» یک درس با عنوان و نام درس بسازید. هنگام دعوت دانش‌آموز در بخش «دانش‌آموزان»، درس موردنظر را انتخاب کنید. دانش‌آموز با حساب موجود کد دعوت را در پنل خود وارد می‌کند؛ سپس همان درس همراه نام معلم در «درس‌های من» دیده می‌شود. برای ریاضی و فیزیک یا دو معلم متفاوت هیچ حساب اضافی نیاز نیست.

هنگام ساخت مأموریت، «درس مأموریت» را مشخص کنید. سرور تنها در صورت عضویت معتبر دانش‌آموز، مأموریت درس‌محور ایجاد می‌کند. دعوت/مأموریت قدیمیِ بدون درس برای سازگاری قبلی همچنان پذیرفته می‌شود؛ ارتباط‌های قبلی خودکار به درس جدید منتقل نمی‌شوند. مدیریت کلاس‌های گروهی، تمرین عمومی، ترک درس، و تحلیل درس‌محور در برنامهٔ توسعه بعدی قرار دارند.

## داشبورد یکپارچه دانش‌آموز

پس از ورود دانش‌آموز، صفحه اول همه درس‌های فعال او را (مثلاً ریاضی و فیزیک نزد معلم‌های مختلف) با مأموریت‌های همان درس نشان می‌دهد. در کارت هر درس تعداد مأموریت‌های تکمیل‌شده، سؤال‌های پاسخ‌داده‌شده، پاسخ درست بدون کمک/با کمک و ارزیابی‌های معلق دیده می‌شود. با فیلتر «نمایش درس» می‌توان یک درس را جدا دید و مأموریت‌های آن را شروع/ادامه داد یا گزارش را باز کرد. تمرین‌های قدیمی بدون درس مستقل نمایش داده می‌شوند. آمار از شواهد ثبت‌شده می‌آید و درصد تسلط مصنوعی ساخته نمی‌شود.

برای آزمایش: `npm run check` و `npm run test:e2e` روی Replica Set؛ تست `student-dashboard.test.ts` جداسازی معلم‌ها و شمارش صحیح/کمکی را پوشش می‌دهد.


## درخواست عضویت در درس، تأیید معلم و خروج

در پنل **معلم > درس‌های من** برای هر درس «صدور / تغییر کد درخواست» را بزنید و کد ۴۸ کاراکتری را مستقیماً و فقط با دانش‌آموز موردنظر به اشتراک بگذارید. کد ۷۲ ساعت معتبر است و با صدور مجدد باطل می‌شود. در پنل **دانش‌آموز > درس‌های من** دانش‌آموز کد را وارد و «ارسال درخواست» را می‌زند؛ تا قبل از تأیید معلم عضویت و مجوز تمرین جدید ایجاد نمی‌شود. معلم در «درخواست‌های منتظر تأیید» درخواست را تأیید یا رد می‌کند.

معلم یا دانش‌آموز می‌توانند عضویت فعال را پایان دهند: تمرین‌های ناتمام آن عضویت لغو می‌شوند، پاسخ‌ها و ارزیابی‌های تاریخی باقی می‌مانند و در بخش «تاریخچه عضویت‌های پایان‌یافته» سابقه عضویت دیده می‌شود. درخواست پیوستن مجدد نیازمند کد معتبر و تأیید تازه معلم است. جریان پیشین دعوت مخصوص ایمیل همچنان کار می‌کند. استفاده از کودکان واقعی نیازمند سیاست رضایت و حریم خصوصی تکمیل‌شده است.

## کلاس‌های گروهی و مأموریت مشترک

معلم پس از ایجاد درس و تأیید عضویت دانش‌آموزان، از بخش «کلاس‌های گروهی» یک کلاس متصل به همان درس با حداکثر ۵۰ دانش‌آموز فعال می‌سازد. اعضا در همین بخش قابل ویرایش‌اند. یک پیش‌نویس مأموریت گروهی با سؤال‌های بانک خصوصی و سیاست راهنمایی/تلاش معلم ساخته و به تمام اعضای ثبت‌شده در snapshot آن مأموریت منتشر می‌شود. **هر دانش‌آموز یک Mission و Assignment مستقل دارد**؛ داده‌های تلاش/پاسخ/بازخورد مشترک نیستند. تأیید دوباره انتشار تکلیف مضاعف نمی‌سازد. گزارش گروهی فقط به معلم مالک نمایش داده می‌شود و دکمه «گزارش اختصاصی» گزارش فعلی همان Assignment را باز می‌کند.

اگر عضویت دانش‌آموز قبل از انتشار پایان یابد، انتشار برای هیچ عضو انجام نمی‌شود تا معلم فهرست را اصلاح و مأموریت جدید بسازد؛ عضویت پس از انتشار هم مطابق روال موجود فقط تمرین ناتمام همان فرد را متوقف می‌کند. تغییر اعضای کلاس روی snapshot مأموریت‌های قبلی اثر نمی‌گذارد. تست‌های اصلی: `tests/integration/class-groups.test.ts` و سناریوی مرورگر Playwright.

## تمرین تقویتی اختصاصی یک دانش‌آموز

تمرکز MVP فردی: معلم در «مأموریت‌ها» از بخش «تمرین تقویتی فردی از اشتباهات ثبت‌شده» یک دانش‌آموز و در صورت عضویت فعال، درس او را انتخاب می‌کند. همیار فقط سؤال‌های تأییدشده بانک خصوصی همان معلم را پیشنهاد می‌کند که **آخرین شواهد ارزیابی‌شدهٔ معتبرشان در آن دامنه، incorrect یا partially_correct** باشد. نتیجه‌های `pending_review` و خطاهای اصلاح‌شده به پاسخ صحیح، پیشنهاد نمی‌شوند. معلم حداکثر ۱۰ سؤال را انتخاب و با تنظیم سیاست مستقل/راهنمایی، مستقیماً برای **همان یک دانش‌آموز** منتشر می‌کند. ارسال مجددِ همان درخواست با Idempotency-Key یک مأموریت تازه ایجاد نمی‌کند. تمرین اولیه و تاریخچه پاسخ‌ها باقی می‌مانند.

دامنه «بدون درس» فقط مأموریت‌های قدیمی فاقد courseId را بررسی می‌کند؛ درس مشخص نیز تنها در صورت عضویت فعال قابل انتخاب و انتشار است. خود دانش‌آموز نمی‌تواند بانک سؤال خصوصی معلم را بخواند یا مأموریت منتشر کند. استفاده عمومی با داده واقعی کودکان همچنان نیازمند رضایت و سیاست حریم خصوصی است.

## بررسی واقعی ۱۲ مرحلهٔ آموزش فردی

سناریو از ثبت‌نام معلم، ایجاد درس، مبحث/مهارت و ۵ سؤال معتبر آغاز می‌شود؛ دانش‌آموز مستقل ثبت‌نام و با دعوت به درس متصل می‌شود، تکلیف پنج‌سؤالی را با خطا/راهنما/پاسخ مستقل حل می‌کند، معلم گزارش و خطاهای واقعی را می‌بیند، سپس تمرین تقویتی ویژهٔ سؤال نادرست را منتشر می‌کند. دانش‌آموز آن را مستقل حل می‌کند و سرپرست دعوت‌شده فقط گزارش محدود خود را مشاهده می‌کند. تست MongoDB واقعی: `tests/integration/full-individual-journey.test.ts`؛ نقشه فلو: `docs/USER_FLOWS.md`.

در فرم تمرین تقویتی، با انتخاب دانش‌آموز نخستین درس فعال او به‌صورت پیش‌فرض انتخاب می‌شود (گزینهٔ «مأموریت‌های قدیمی بدون درس» همچنان موجود است). سؤالِ دارای تمرین تقویتی باز دوباره پیشنهاد نمی‌شود؛ بعد از تکمیل آن، نتیجهٔ تازه برای تصمیم بعدی استفاده می‌شود. ثبت‌نام والد به معنی احراز حقوقی سرپرستی نیست.
